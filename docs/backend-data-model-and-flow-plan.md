# ProTangram 后端业务数据与流转说明

本文说明业务对象、关联关系和数据如何流转，不规定数据库、接口或代码如何实现。依据《电涵道风扇试验数据结构.html》及当前前端业务概念；具体技术设计由后端开发者决定。

## 1. 物理对象：分类、组成与参数

HTML 将对象分为产品对象、试验设备和陪试件。每个对象可以有自己的编号、别名、照片、图纸/三维模型、说明文档、参数及组成关系。对象类别决定默认可用参数，但用户应能修改对象参数值，也能按业务需要新增参数定义；“修改一个对象的参数值”和“新增一种参数定义”是两件不同的事。

| 对象类别 | HTML 中的组成关系 | 当前定义的主要参数 |
|---|---|---|
| 分布式电推进系统 | 10 个电推进动力单元、动力电池、集成式短舱系统 | 系统级参数按实际需要定义；组成关系可查看各下级对象 |
| 电推进动力单元（L1–L5、R1–R5） | 单涵道风扇动力装置 + 对应短舱单元 | 继承或引用组成对象的参数；HTML 说明十个单元共用一台动力装置、各自对应不同短舱单元 |
| 单涵道风扇动力装置 | 涵道风扇、电驱系统、若干结构件 | 外包络尺寸说明、机匣包络轴向长度、质量 |
| 涵道风扇 | 机匣 ×1、转子/静子 ×2 | 叶尖直径、涵道内径、轴向长度、转静子轴向长度、轮毂直径、外包络尺寸、旋转方向、材料、设计点类型、设计值表 |
| 机匣 | 可继续包含若干部件 | 内径、外径、长度、材料 |
| 转子 / 静子 | 可继续包含若干部件 | 叶片数、叶栅稠度、中弦长、叶根弦长、叶尖弦长 |
| 电驱系统 | 电机 ×1、电机控制器 ×1 | 直径、轴向长度、工作电压/电流范围、最大起飞/连续/巡航功率、最大转速、质量、冷却方式 |
| 电机 | 定子组件、转子组件及其他部件 | 电机直径、额定功率、绕组接线方式、几何高度、额定转速、极对数、质量、额定扭矩、电机速度常数、气隙、额定持续电流、反电动势系数、铁芯长度、峰值功率/转速/扭矩、d/q 轴电感等 |
| 电机控制器及功率模块 | 控制器包含至少一个功率模块及其他部件 | 控制器：线电压、功率因数、电机效率；功率模块：型号、品牌、电压、导通电阻、持续漏极电流、功率耗散等 |
| 动力电池 | 电芯、BMS 及其他部件 | 按 HTML 已定义字段填写；未定义的电池专用参数可后续补充 |
| 短舱单元 / 集成式短舱 | 各自可以包含若干部件 | 通用对象信息及实际需要的尺寸、材料、质量等参数 |
| 试验设备 | 试验台、测量设备、供电设备 | 试验台：型号、设备编号、流量/温压范围、测量范围与误差等；测量设备：型号、量程、误差、数量、采样频率、计量证书与有效期；供电设备：额定功率、输出电压 |
| 陪试件与工装 | 可继续包含普通部件 | 尺寸说明、材料、图号、数量 |

参数表是 HTML 当前定义的主要字段，不是封闭清单。对象组成关系也不等于试验时一定使用的对象：产品组成回答“它由什么构成”，试验构型回答“本次试验组合了什么”。

**需要明确的对象身份问题：** HTML 将 OBJ 解释为有编号的实际实物，但部分实例使用“涵道风扇方案 1”等设计方案名称。后端应说明设计方案/设计参数与实际实物/实测状态如何区分或关联，不能仅凭名称把两者视为同一概念。对象发生改装、技术状态变化时，HTML 约定建立新的对象，并通过“演变自”追溯原对象。

## 2. 试验如何引用对象、方案、载荷谱与 CSV

HTML 中相关概念的职责如下：

| 概念 | 含义及关联 |
|---|---|
| TASK 试验任务 | 组织一组相关试验，可关联任务书或试验大纲 DOC |
| SUBJ 试验科目 | 定义一类试验、试验对象、测量内容和变量 |
| SET 试验设置 | 一种变量取值组合；可引用 PROG 程序和 CFG 试验构型 |
| CFG 试验构型 | 由被试对象（必需）、供电对象（可选）和陪试件（按需）组成 |
| PROG 程序 | 保存载荷谱、采点表、时间段、控制目标或转速与采点数等内容 |
| COND 工况、REQ 要求集 | 描述试验/模型使用的工况及对应要求值、上下限 |
| DOC 文档 | 任务书、试验大纲、设计文档等依据文件 |
| FMT 采集格式 | 描述 CSV 编码、表头行数、时间列、采样频率、无效判据及各列含义 |

“试验方案”一词需要按语境区分：如果指实际执行的载荷谱或采点程序，对应 HTML 的 PROG；如果指可复用的计算方法/仿真模型，对应 MODEL。两者不能因名称相近而合并。

按当前希望的简化方式，**CSV 文件直接作为试验记录来说明，并直接关联具体试验**；关联位置即表达归属，不额外增加复杂的文件/记录层级。一个具体试验可以关联多份 CSV。导入后保留原始文件，按需要用 FMT 解释列名、物理量、所属部件、测量位置、传感器和单位；图表或分析结果直接引用相应 CSV 及列，便可说明其数据来源。

这与 HTML 原有 REC 定义存在一处差异：HTML 的 REC 指一次实际执行，并可关联采集文件；示例中一条记录关联四份采集文件。为避免将两种含义混用，文档采用“CSV 作为业务记录单元”的简化口径；如果后端必须兼容原 HTML 数据，应明确该映射如何处理，不要默默增加额外层级或丢失原有关联。

## 3. 通用模型、对象模型、数据标定与预测结果

| 概念 | 含义 | 关联与用途 |
|---|---|---|
| MODEL 通用模型 | 可复用的计算方法或模型基础，例如气动性能模型（CFD） | 记录模型类型、版本、适用范围、输入/输出定义、方法文件和验证精度说明 |
| OM 对象模型 | 将通用模型应用于具体对象或设计方案后的模型配置，例如“方案 1 气动模型（CFD）” | 必须关联一个通用模型，并关联一个或多个仿真对象；记录几何参数、模型参数、边界条件及每个参数的来源 |
| 标定/验证数据 | 用于调整模型参数或检验预测精度的仿真数据、实测数据 | 按需关联对象模型；实测数据可来自试验 CSV。并非所有模型都必须使用同一种标定流程 |
| 预测输入 | 对象参数、运行工况、边界条件及用户提供的其他输入 | 运行前确定本次采用的参数值和来源，避免对象参数后来变化后无法解释旧结果 |
| 预测结果 | 模型输出的表格、曲线或指标，如推力、流量、推力系数 | 关联本次使用的对象模型、目标对象、输入条件和来源数据，以便查看和复核 |

模型数据流为：选择目标对象/设计方案 → 读取该对象适用的参数并补充工况与边界条件 → 选择其关联的 OM → OM 调用对应 MODEL → 生成预测结果。标定与验证是相关但不同的支路：选择合适的仿真或实测 CSV → 关联到对象模型 → 用于模型标定或精度验证 → 保存对应说明和结果。

截图中的“0.75D · 安装探针 / 记录1”是否属于标定数据，需要按实际关系确认；不能只根据它出现在关系图中就认定它参与了模型训练。通用模型可以复用，但不同对象模型应明确目标对象和参数来源，不能仅因参数名称相同就默认来源相同。

## 4. 从对象到成果的完整数据流

对象类别/参数定义 → 创建或选择具体对象及其组成 → 建立试验科目和具体试验 → 选择被试对象、按需选择供电对象/陪试件/试验设备，并引用适用的 PROG、CFG、COND、REQ、DOC → 导入该试验的 CSV → 根据 FMT 识别数据列 → 查看数据、生成图表或分析结果 → 按需将 CSV 作为模型标定/验证数据，或作为预测结果比较依据 → 选择 MODEL 与对象模型 OM，读取对象参数和工况运行预测 → 保存预测表格/曲线及其来源 → 项目或任务书按关联关系汇总试验与成果。

其中，项目和任务书只负责组织、关联与汇总，不应复制试验、CSV 或图表。试验可以先独立存在，之后再关联任务书或项目；同一具体试验可以被多个项目引用。原始 CSV、图表与模型结果之间应保留直接可理解的来源关系，不要求用户理解复杂的内部技术分层。

## 5. 需要后端明确的少量事项

1. **设计方案与实物的身份边界：** 例如“涵道风扇方案 1”是否代表设计对象、实际样机，或二者之间存在关联；这会影响模型绑定对象的含义。
2. **CSV 与执行记录的映射：** 本说明按 CSV 作为记录单元简化；HTML 原始 REC 可关联多个文件，后端需要明确兼容方式。
3. **模型适用范围和数据用途：** 明确哪些 CSV 被用于标定、哪些用于验证、哪些仅用于结果比较；不能将“已关联”自动等同于“已参与训练”。
4. **关系的必需性：** CFG 的被试对象是必需的，供电对象可选、陪试件按需；模型对象和标定数据则按模型业务规则处理。其他关系不应一律强制。

本说明只定义业务含义和数据流转。后端开发者自行决定持久化方式、数据结构、接口组织及实现步骤，并以这些业务关系为依据给出简明设计和验证结果。
