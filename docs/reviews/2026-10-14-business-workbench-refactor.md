# 物理对象与试验工作台业务重构

本次按照“物理对象 → 具体构型 → 试验构型 → 具体试验 → 执行记录 → CSV → 图表、数据表及专业成果”调整现有前端，未增加后端或专业算法。

## 业务与界面变化

- 具体试验登记载荷谱名称或编号，可选说明与任务书 ID。删除创建、编辑过程中的复杂设计工况表和预先定义的测量输入，不要求录入载荷曲线或执行控制量。
- 每个具体试验使用 `records[]` 保存多次执行；每条记录具有稳定 ID 与执行序号，并独立保存原始文件、图表及数据表。一个记录可以拥有多个 CSV，多个文件不会创建多次执行。
- 只有一次记录时直接展示内容；多次执行时由详情中的执行列表明确选择，未选定时不会自动改用其他记录。失效记录 ID 始终显示失效提示。
- 图表、文件及数据表写入均要求准确的具体试验 ID 和记录 ID。图表和数据表只允许选择所属记录的 CSV 字段。
- CSV 数据表支持保存名称、显示字段和行范围，刷新后恢复；不复制 CSV 内容。其列名直接来自 CSV，包含名为 `key` 的字段时也不会被表格组件的行键覆盖。
- 试验构型的原设置与参数合并为一组“试验构型参数”，沿用批量名称、内容、单位、独立描述及加号录入。尚无执行记录时可以编辑；已有执行记录后只更正名称和说明，参数变更需建立新试验构型，避免改写历史含义。
- 具体构型技术参数的编辑操作移至每行最右侧，删除模型定义入口、模型登记表单和对应新增动作。历史模型契约仍供专业模块读取，专业模型选择与各自输入参数保留。
- 删除左侧重复的专业功能导航。保留工作台的工具入口及记录上的专业操作，专业功能独立使用时仍可主动选择来源。
- 任务书关联视图支持在已有试验构型中发起具体试验，自动带入任务书 ID；也支持关联已有自主试验。两条入口操作同一实体，不产生第二套试验系统。
- 专业会话、成果和报告保持按业务 ID 引用。两次执行进入不同会话；更改任务书关联后，相关上下文从具体试验读取最新关联。已保存设计成果仍可按引用用于后续试验，并可解除该引用。

## 既有数据保留

前端持久化版本升级为 4，存储键保持 `protangram-physical-objects-v1`。

版本 0 的旧记录数组、版本 2 的试验构型记录、版本 3 的具体试验当前记录及历史记录，统一迁移到具体试验的 `records[]`。保留原具体构型、试验构型、具体试验、记录、原始文件、图表和专业成果 ID；旧记录的实际条件、测量备注、设计工况及设计引用也保留。IndexedDB 中原始文件的 ID 不变，无需搬迁或重新上传。

旧设置及参数合并时保留说明、单位、形式和来源。如果参数 ID 相同而内容不同，保留两份内容并为旧设置分配兼容 ID。部分已迁移的数据会补入同一稳定试验，不产生重复实体；无记录的旧任务书关联也保留为具体试验关联。

旧数据没有载荷谱时显示待补充，不猜测原载荷。原记录仍可访问；补充标识后才能新增执行记录。旧链接缺少具体试验 ID 时，可以按明确的记录 ID 恢复所属试验；若明确的试验或记录 ID 无效则不回退。

已修复并测试首次模块加载时的迁移初始化顺序，避免“存储仍存在但页面为空”。迁移具有幂等性，刷新不会重复建立记录。没有使用清空状态的方式升级数据。

## 实际验证

- 12 项物理对象/记录/迁移测试通过，包含首次导入 Store 时带有既有 v3 数据的同步恢复。
- 10 项跨功能数据引用测试通过，包含两次执行的会话、图表及旧报告引用隔离。
- 27 项既有会话工作台回归测试通过。
- `npm run build` 和改动文件的 ESLint 通过。
- `scripts/verify-physical-source-interactions.mjs` 的 13 个真实 Chromium 场景通过：创建物理对象及 A/B 构型、批量参数与 Tooltip、参数右侧编辑、试验构型编辑、自主试验、多个 CSV、两张图表与数据表、两次执行、失效 ID、来源继承、任务驱动创建与关联、刷新、旧数据迁移及窄屏导航。
- `scripts/verify-cross-function-sharing.mjs` 的 14 个真实 Chromium 场景通过：分析成果保存与刷新、校准成果引用、虚拟工况引用、旧模型契约及独立参数、图表报告与历史报告、设计引用及解除、记录返回及跨来源隔离。

浏览器测试使用本地 Vite 的 `http://127.0.0.1:5173`，使用隔离的临时浏览器配置，不操作用户已有浏览器的数据。核心流程脚本拦截所有服务端写请求，实际没有产生这些请求；页面运行错误为 0。中文截图使用当前环境可读取的 Windows 字体。现有开发服务器保留运行。

可复核结果位于 `frontend/node_modules/.tmp/physical-source-interactions/results.json` 与 `frontend/node_modules/.tmp/cross-function-sharing/results.json`；核心截图位于前者目录。

## 边界

本轮需求无未完成项。旧数据的载荷谱标识需要用户按真实业务补充；无法由软件推断。专业模块既有演示计算及其标识保留，不声称实现真实校准或预测。
