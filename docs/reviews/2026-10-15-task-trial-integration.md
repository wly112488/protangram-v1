# 任务书、试验资料与报告整合

## 页面与流程

- 任务书列表、左侧任务书链接和旧任务书 URL 统一进入 `/task-center?taskId=…`。物理对象页面只保留对象与试验、独立专业功能；移除内嵌的另一套任务书关联页面。
- 任务书详情按具体物理对象和试验构型分组，展示具体试验、载荷谱、各次执行、CSV 文件、图表、数据表和专业成果。点击试验或执行记录进入原始页面。
- 具体试验创建和编辑仍可选择、调整或清除任务书关联。编辑关联保留当前记录 ID，不要求回任务书重新管理。
- 新建关联试验复用原试验页面，只传入试验构型和任务书上下文；关联已有自主试验只更新其任务书 ID。
- 任务书原始 PDF 沿用既有 IndexedDB 存储，可上传、更换和实际预览；历史正文、事项与引用保留。

## 数据和报告

`taskTrialModel.ts` 从物理对象 Store 和成果 Store 按任务书 ID 生成实时投影，未给任务书增加试验、记录、CSV 或成果副本。

任务书统计包含跨设备、跨试验构型、跨执行记录及专业会话成果空间的数据。图表和报告材料按设备、试验构型、具体试验、执行记录及图表 ID 引用；相同图表名称不会合并。

任务报告复用已有章节、报告配置和编制页面，保留手工正文及已有报告。当前任务的图表和专业成果自动成为可选资料，内部沿用原报告配置，无需用户重复选择数据来源、项目或模板。演示成果保留标记，不能用于完成人工任务报告。AI 整合生成尚未接入，没有提供模拟 AI 补全或自动执行入口。

“查看报告”已替换为实际正文、成果和原始 CSV 图表预览，不再仅显示占位成功提示。报告编制完成只保存本机编制成果，不自动改变任务完成状态。

试验改关联其他任务书后，两个工作台的范围实时更新。历史报告与引用保留；若其试验已不属于当前任务，新一轮报告编制会提示来源变化并阻止继续使用失配来源。任务报告中新选资料也会排除已移走记录的成果。

## 验证

- 70 项代码测试通过：物理对象 15、跨功能引用 11、既有会话 27、任务书与试验投影 5、报告模型 6、任务报告证据 6。
- 改动文件 ESLint 和生产构建通过。构建仍有既有的大包体提示。
- 既有物理对象浏览器流程 13 项、跨功能浏览器流程 14 项通过。
- 新增任务书整合专项浏览器场景 7 项全部通过，合计 34 项真实浏览器场景通过，页面运行时异常为 0。脚本 `frontend/scripts/verify-task-trial-integration.mjs` 覆盖 PDF、正常试验流程中的关联、多 CSV、多次执行、跨设备汇总、成果来源、人工报告、实际图表预览、关联调整及旧入口兼容。最终结果见 `frontend/node_modules/.tmp/task-trial-integration/results.json`。

浏览器测试使用隔离配置，专项测试拦截服务端写请求，不操作用户已有浏览器数据。后端同步 GET 失败和既有专业演示算法不在本轮实现范围；本轮验证的是前端本机资料、引用、持久化和交互，不代表真实后端计算或 AI 报告算法已经实现。
