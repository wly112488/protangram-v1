# 底部工作表、通用绘图与来源成果目录

**Goal:** 实施讨论后确认的工作流：专业功能上方工作，底部上拉工作表；右键绘图跨功能复用；成果按业务来源组织。

**Architecture:** SessionWorkbench 持有试验级工作表 Provider，避免功能路由切换销毁未保存编辑。CSV 仍属于原执行记录，编辑保存为带来源 ID 的工作副本。图表继续使用现有 charts 存储与渲染，增加可选多字段/绘图配置以兼容旧图。成果目录只引用已有数据。

**Tech Stack:** React、Ant Design、Zustand、IndexedDB、PapaParse、ECharts，沿用现有 Node/Playwright 检查。

## 确认的边界

- 五个专业功能不变；绘图作为工作表通用操作，不再仅属于数据分析。
- 标签固定底部，向上展开、拖动高度、收起、重命名和关闭视图；关闭视图不删除文件。每个专业功能保留自身打开的标签。
- 所有列展示，每页默认 15 行，用数字分页。支持选列、Ctrl/Shift 多选、直接输入/双击编辑和字段重命名。
- 先选列右键绘图，或先选图形再指定字段；仅显示当前图形必要角色。不常驻 X/Y 配置。
- 多曲线、散点、柱状、直方图、箱线、气泡等使用现有 ECharts 二维能力；不伪装支持未安装的三维渲染。
- 现成换算公式没有真实目录接口，明确标示未接入；不编造领域公式。可支持明确选用的本机按点分组平均，保存参数并保留原 CSV。
- 进入根因分析默认收起表格，固定标签仍可切换 CSV 和对应结论；需要查数据时再展开，之后切换文件保留用户的展开选择。
- 根因分析范围始终是当前单个 CSV，切换 CSV 同步切换状态/结果；真实诊断服务未接入时不拿内置样例冒充该 CSV 的结论。保留旧演示入口并明确与真实文件分离。
- CSV 导入/删除仍只在数据分析；保存成功文案明确本机持久化，后台缺口不冒充打通。
- 专业页面不再嵌入共享成果目录。左侧共享成果页以试验/载荷谱 → 执行 → CSV → 成果组织，无 CSV 或多来源成果保留在其真实业务范围，不重复复制。
- 功能来源保留为元数据，不作为固定第一层分类。历史成果/报告兼容可查看。

## 实际实施说明

- `TrialWorksheetProvider.tsx` / `TrialWorksheetDock.tsx` / `trialWorksheetContext.ts` / `trialWorksheet.css`：试验级持有编辑器，专业功能分别保存打开的标签和活动文件；底部固定、向上展开、拖动/键盘调整高度、收起/最大化、重命名/关闭视图。只访问过的文件才读取内容。
- `CsvWorksheetEditor.tsx` / `WorksheetPlotDialog.tsx` / `worksheetPlotModel.ts`：全部列、默认 15 行数字分页、鼠标与键盘编辑、Ctrl/Shift 选列；通过表格右键或“绘图”按钮调用当前图形的字段配置。支持折线/散点/分组柱状/直方/箱线/气泡；没有三维渲染依赖，不提供假的三维入口。
- `physicalObjectStore.ts` / `trialChartOutput.ts`：保留现有图表存储及旧双列图兼容；可选多曲线、气泡大小字段、分组平均和发起功能元数据；预览、共享查看及 PNG 导出走同一渲染路径。分组平均明确按原始行分组，排除无效数值配对，不代表按时间重采样。
- `TrialCsvAnalysis.tsx` / `TrialDataAnalysisWorkspace.tsx` / `CsvDiagnosisResults.tsx`：导入/移除唯一入口，多个文件保存在同一次执行；异常分析按当前单个 CSV 展示，保存结果可选择后查看图形/结论和依据。演示样例单独标明，不能成为当前 CSV 的真实结论。
- `resultCatalogModel.ts` / `AnalysisResults.tsx` / `ResultPreview.tsx` / `analysisResultModel.ts` / `ProjectContent.tsx`：去掉五功能目录第一层，按实际试验、载荷谱、执行、CSV 及成果组织；多来源/无 CSV 成果放在真实执行或试验范围；方案/预测等成果仅携带可用文件上下文，不代表由 CSV 计算产生，不据此强行归到 CSV；点击才预览，报告和移除来源警示保持兼容。
- `SessionWorkbench.tsx`：五功能接入统一工作表生命周期，移除旧功能下文件卡片/重复工作表；旧 `TrialCsvReferences.tsx` 删除。专业功能下没有共享成果目录。
- `verify-csv-result-workspace.mjs` 转向当前工作流检查，避免保留两套相互矛盾的 UI 测试。

### 后端核查

现有 `backend/src/index.js` 提供通用 `/api/data-processing-config` 和 `/api/compute/:moduleId/:algId`，以及基于服务器已有 `filePath` 的 `/api/data/read-chunk`。这些接口不等于本工作流已有文件上传、CSV 编辑版本/分页或领域标定公式目录；未发现真实按单 CSV 诊断的接口。此次没有更改后端模型或伪造这些接口成功。

原始 CSV、工作副本及图表仍沿用本机 IndexedDB/现有 store；界面明确本机保存。平均处理为本机真实计算，原始数据不覆盖；绘图处理不悄悄影响根因输入。领域换算公式、不同时间基准的采样对齐与真实自动诊断保留为明确后端缺口。

### 复核修正

独立代码复核发现并修复：

1. 保存期间禁止取消/关闭，避免写入等待阶段出现新编辑被复位；保存后同步恢复初次加载的不可变原始快照，没有异步回读覆盖窗口。
2. 绑定旧执行记录的会话也能查看同一试验其他执行 CSV 的诊断；先按试验取成果，再按文件及真实所属执行筛选。
3. 报告也执行统一来源有效性检查；共享目录覆盖具体试验全部执行。

TDD 证据：目录测试先以旧五功能分组失败，再通过；多列/平均/气泡测试先在旧双列渲染上失败，再通过；单 CSV 排他/报告失效测试先失败，再通过；慢写入取消检查先 `false !== true`，修复后通过；延迟源文件读取 15 秒时旧实现将新编辑 4777 覆盖为 3000，改用不可变快照后通过。
