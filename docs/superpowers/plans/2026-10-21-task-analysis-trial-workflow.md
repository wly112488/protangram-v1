# 任务书分析与试验工作流

**Goal:** 独立导入任务书、预填试验草稿、复核后进入已有试验工作台，任务跟踪进度，确认完成后显示左侧会话。

**Architecture:** 复用 TaskRequirement、任务文件存储、TrialCreatePage 和五个专业功能。任务规划只增加可选前端草稿/来源引用；试验、执行记录、CSV、成果仍使用原存储。项目只填名称创建，物理对象导航放底部默认收起。

## 已确认约束

- 分析任务书是独立功能；不强制创建项目。
- 导入后展示待复核的试验模板，已有信息自动带入，未确定字段留空。页面不展示服务接入、模型选择等技术信息。
- 本轮复用已有前端任务拆解展示；PDF 为原文预览，前端建议不伪造原文页码、专业参数或 AI 服务响应。
- 复核确认前不创建正式试验/会话；确认后使用真实稳定 ID 关联。
- 工作会话在任务里继续，事项确认完成后显示左侧；同一试验不重复生成会话或成果。
- 完成进度依据真实事项状态，完成需填写依据或关联已有成果。
- 保留现有数据和前端持久化方式，不变更后端数据模型，不复制试验/成果。
