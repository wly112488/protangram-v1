# ProTangram 工作台项目树 UI 重构设计

## 目标
在不改变现有业务逻辑、路由、数据契约和 AI 助手行为的前提下，重构 ProTangram 前端工作台展示，使项目、已生成内容和业务功能入口的关系更清晰，并参考已确认 HTML 原型的视觉语言提升易用性。

## 范围
本次只重构展示层。

保持不变：
- `BusinessRouteState`、`ModelContract`、`TaskContract`、`DataContract`、`ResultContract`、`ValidationContract`、`PlanCondition` 等业务契约。
- 数字孪生、智能试验设计、试验数据分析、虚拟工况扩展之间现有跳转和传参逻辑。
- `TrialAIAssistant` 的上下文、快捷动作、业务动作与悬浮抽屉交互。
- DOE 快速设计、模板设计、关联对象管理、报告等现有功能行为。
- 后端接口和持久化格式。

不新增：
- 新的项目实体模型。
- 算法结果自动写入左侧项目树的持久化逻辑。
- 新的业务流程、按钮或算法能力。
- 固定右侧 AI 面板。

## 设计原则
1. 顶部负责稳定业务能力入口，左侧负责项目及已存在内容，中央负责当前内容展示。
2. 左侧树只展示当前前端已经持有的数据，不伪造尚未执行的分析、校准或虚拟工况结果。
3. 项目树在根工作台和业务子路由中保持可见，避免用户进入功能页后失去项目定位。
4. 现有业务页面继续通过 React Router `Outlet` 渲染，不重写页面内部业务逻辑。
5. 视觉参考已确认 HTML 的浅蓝灰背景、白色圆角面板、弱边框、轻阴影、紧凑层级，但不复制其固定 AI 栏或虚构业务字段。

## 页面架构

### 顶部区域
保留 `试验管理 / 试验设计（DOE） / 数据分析 / 报告生成` 作为一级功能入口。

`FunctionBar` 继续持有现有 Popover、Modal 和路由行为，仅调整视觉样式和空间组织。

`MainLayout` 保留品牌、用户、主题和 AI Provider；避免为了视觉重构迁移业务状态。

### 左侧项目树
左侧固定宽度约 230–250px，可拖拽调整范围保持现有能力。

一级节点：当前已导入或已生成的实验/项目对象。

二级节点只来自现有前端数据：
- 项目概览：始终可用，用于回到当前项目默认工作区。
- 试验工作表：当前项目存在工作表数据时展示。
- 设计摘要：当前项目已有 `designSummary` 时展示。
- `extraItems`：继续原样展示已有扩展项。

不在本次重构中预先增加“数据图表 / 根因分析 / 校准结果”等节点，因为当前 `GeneratedExperiment` 未保存这些结果的存在状态。后续如业务逻辑真正写入 `extraItems` 或统一项目资源模型，可自然进入左侧树。

交互：
- 一级节点可折叠。
- 点击一级项目，选中该项目并回到“项目概览”。
- 点击二级节点，更新当前项目和内容选择；如果当前位于业务子路由，则导航回 `/` 展示工作台内容。
- 切换顶部业务功能时，左侧项目树不消失。

### 中央工作区
根路由 `/`：
- 无项目：展示轻量空状态，不重复新增“新建/导入”按钮，提示从顶部现有功能进入。
- 选中项目概览：展示项目名称、设计方法、试验规模等现有可确定信息；不展示虚构模型、异常、可信度等数据。
- 选中试验工作表：突出当前 worksheet。
- 选中设计摘要：继续复用现有设计摘要内容。

业务子路由：
- 中央区域直接渲染现有 `Outlet` 页面。
- 左侧项目树和顶部 FunctionBar 继续保留。
- 不更改 DigitalTwin、IntelligentExperimentDesign、AnalysisExecution、VirtualConditionExtension 等页面内部状态和业务动作。

### 试验工作表
保留现有底部工作表能力和可调整高度，但移除视觉上过强的整条横向实线分隔。

根工作台中：
- 项目概览可同时看到概要与工作表。
- 试验工作表节点可让工作表成为主内容。
- 设计摘要视图仍可保留工作表作为下方数据区。

业务子路由不强制显示底部工作表，避免挤压现有业务页面。

### AI 助手
`TrialAIAssistant.tsx` 不改业务逻辑。

继续采用现有右下角悬浮按钮 + Drawer：
- 页面上下文由各业务页现有逻辑设置。
- 快捷问题、Mock 回复和 `BusinessAction` 回调保持一致。
- 不新增固定右侧 AI 栏。

## 组件改动

### `frontend/src/workbench/ExperimentWorkbench.tsx`
主要重构点：
- 让左侧项目树成为根路由和业务子路由共用的固定壳层。
- 将根工作台内容拆成空态 / 项目概览 / 设计摘要 / 工作表视图。
- 保留现有 `GeneratedExperiment`、localStorage、导入与 DOE 生成逻辑。
- 保留左右、上下拖拽调整逻辑；仅调整布局和边界样式。

### `frontend/src/workbench/FunctionBar.tsx`
- 不改点击处理和所有 Modal。
- 仅调整顶部导航视觉，使其接近确认原型的简洁横向导航。

### `frontend/src/layouts/MainLayout.tsx`
- 保留结构和功能。
- 仅做必要视觉收敛，确保与新工作台背景、圆角和间距一致。

### `frontend/src/index.css`
- 新增或调整以 `layout-` / `workbench-` 为范围的样式。
- 不依赖新增 CSS 文件。
- 尽量不影响原有业务页面 Ant Design 组件。

### 不改文件
除非类型检查暴露必要兼容问题，否则不修改：
- `frontend/src/components/TrialAIAssistant.tsx`
- `frontend/src/types/businessContext.ts`
- `frontend/src/router/index.tsx`
- 后端代码和数据文件。

## 数据流
现有数据流保持：

`FunctionBar 操作 -> ExperimentWorkbench 回调 -> GeneratedExperiment / localStorage -> 左侧树与工作表`

业务子页面保持：

`React Router -> 页面组件 -> BusinessRouteState / localStorage -> 下游业务页面`

AI 保持：

`业务页面 setContext -> TrialAIAssistant Drawer -> BusinessAction 回调`

本次不增加左侧树到业务结果的数据同步链路。

## 异常与边界
- 没有项目：左侧显示空状态，中央显示工作台提示；顶部独立功能仍可使用。
- storedExperiments 有数据但尚未导入当前工作台：不自动全部打开，保持现有导入逻辑。
- 项目切换后若当前二级节点在目标项目不存在，回退到项目概览。
- 子路由页面不依赖当前项目时仍正常打开；左侧项目树仅作为持久工作区导航，不改变页面业务参数。

## 测试与验收
1. `npm run build` 通过，TypeScript 无新增错误。
2. 根路由无项目时可正常显示，顶部功能可使用。
3. 通过现有流程生成或导入项目后，左侧出现一级项目节点并可折叠。
4. 项目概览、设计摘要、工作表切换正确，不产生虚构分析节点。
5. 进入数字孪生、智能试验设计、数据分析、虚拟工况、报告等现有路由时，原页面功能和传参不变，同时左侧项目树保持可见。
6. AI 悬浮按钮、Drawer、快捷问题和业务动作行为与重构前一致。
7. DOE 快速设计、模板设计、关联对象管理 Modal 行为与重构前一致。
8. 主工作区不再存在强横向实线分割，视觉采用确认原型的浅蓝灰背景、白色圆角面板和弱阴影。
